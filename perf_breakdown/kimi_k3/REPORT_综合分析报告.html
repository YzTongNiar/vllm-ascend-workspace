7.P vs D：访存 / 通信 / 计算 bound 对比

7.4 Attention / MoE 的 bound 结论

组D ep32P A3_p
Attention计算 bound（流水 59% vs 访存 41%；FlashMla 计算 + RecurrentKda vec 计算）均衡偏计算（51% vs 49%；ChunkKdaFwd 计算主导 + FusedInfer 拉回访存）
MoE访存 bound + 通信显著（44% vs 56%；dispatch/combine 组内 4.3ms = MoE 的 14%，另有 RS/AG 在组外）访存 bound（48% vs 52%；a2a dispatch 记在通信桶未入组，计入则通信占比更高）
核心洞察：① D 的 MoE（占 busy 43%）是访存 bound——w4a8 NZ 权重组矩阵乘 mac 仅 ~50%、搬运 170%+，Cube 没喂饱；专家流独立成流正是用访存并行度换吞吐，优化方向是权重布局/缓存友好、增大合并粒度。② P 的主要 bound 是通信（去重后 ≈55%）而非计算/访存——KV broadcast + a2a + send 重叠不足，优化优先级高于算子本身。③ 量化/反量化类在 P 侧合计 ~370ms/前向（DequantSituQuant 为 vec 计算主导）——融合进 GroupedMatmul（D 侧 SituQuant 做法）可同时省计算与访存。

scalar bound 的来源：Ascend scalar 流水承担地址算术 / 索引与循环控制 / gather-scatter 寻址 / 逐 tile scale。大小核 scalar 偏高 = ① paged KV 的 block_table 间接寻址（每页装载前先算地址，~105 页×32 序列 = 每次数千次地址计算）；② KV 首轴非连续（见 8.6）使 MTE 无法跨页连续 burst，退化为逐页分段搬运；③ fp8_ds_mla 逐 tile 自带 scale 在 scalar 处理。是"规则但间接"的访存，不是随机离散。

7.6 KV 首轴非连续（vllm-ascend PR #18256）——Kimi K3 为什么 KV 不连续

含义：cache 形如 [pages, block=128, heads, dim]，首轴=页维。"连续"要求 stride(0) = 128×heads×dim（页与页紧挨）；首轴非连续 = stride(0) 大于该乘积——逻辑页之间夹着 padding 或其他数据。

K3 的三个成因：

#成因具体几何（PR 测试代码实测值）
1hybrid 池共池对齐：K3 = MLA 注意力 + KDA（类 Mamba 线性注意力）混合模型，MLA 页与 KDA conv/SSM state 页从同一页对齐池分配，物理页含对齐 paddingstride(0) = 物理页字节数（含 padding），逻辑页更小 → 页间有洞
2component-major 交错：MLA 的两个分量（latent nope 512 + rope 64）按页交错存进同一 raw bufferraw [blocks×2, 128×576]；nope 视图 stride(0)=2×page、offset 0；rope 视图 stride(0)=2×page、offset 128×512 —— 页序为 [nope₀][rope₀][nope₁][rope₁]…，首轴步长是逻辑页的 2 倍
3多个 MLA 层共享 backing tensor，各自视图带不同 storage_offset同池多视图，无法全局稠密化

为什么不直接拷成连续：稠密化要么把 padding 物化（浪费显存），要么每层多一次拷贝；PR 18256 选择保持 vLLM block-table 语义不变，用 as_strided 暴露真实几何（make_page_strided_cache_view），并把所有 strided 读写路由到 stride-aware 的 npu_mla_prolog_v3（替换 AutoContiguous writer；DCP strided decode 同路）。代价-收益闭环：scalar 流水上升（8.5）<-> 省掉稠密拷贝与显存；profiling 里 MlaPrologV3 每层一次（24/步）正是这条路由的指纹。（源码：本地 pr-18256 分支，docs/non_contiguous_kv_cache.md；30 文件 +4266 行）
